# Extension validation

Source implementation: commits `a6acf95` and `807676d` on `gabenapoleone3-ai/trading-lab`.

- **76 unit/integration tests passed**, including the preserved project tests and new model, timeframe-boundary, context, stale-signal, provider validation, forward/history separation and chart-coordinate tests. Both the existing dashboard production build and extension build passed. `npm audit` reports zero vulnerabilities.
- **Two deterministic packaged MV3 browser tests passed** on the GitHub Chrome for Testing runner. They load the actual built extension in a temporary profile and test context changes, settings/key isolation, source-validated synthetic provider fixtures, BUY calculation, chart markers, forward observations, unsupported panes, key-free exports and missing-credential WAIT behavior. Synthetic fixtures are test-only and excluded from the installable package.
- **Actual public Supercharts + packaged MV3 test passed** on the same runner, with no API keys: the real `www.tradingview.com/chart/?symbol=NASDAQ:AAPL` page loaded the extension's on-page badge and the content adapter reported AAPL/daily. No TradingView private data or API was consumed. Public toolbar metadata was also inspected directly in the cloud browser; this caught/fixed current ID-based controls versus older `data-name` selectors. A local direct interval-menu attempt was unavailable in that managed/limited chart session; automatic ticker/interval change handling is covered by the deterministic browser test, not represented as an authenticated live-data check.
- Full opt-in live run: https://github.com/gabenapoleone3-ai/trading-lab/actions/runs/40247452628 — all steps succeeded, including the three Chrome extension tests. The regular run skips the explicitly opt-in external-site test; skips are not counted as passes.
- The existing dashboard GitHub build/test job passed. Its Pages deployment still fails at Pages configuration because Pages is disabled and administration permission is unavailable. The extension does **not** depend on Pages to install or run.
- The cloud system Chromium has an organization-managed extension blocklist. Its policies were not changed. Packaged extension tests ran in the separate GitHub test runner. The direct public-site browser check used the platform-provided CA in a temporary trust profile, without disabling TLS verification.
- Release package checked: Manifest V3, only the Alpaca data host permission, no brokerage endpoints, no runtime state, no `.env`, no test credentials or fixtures, no source tests. Dependency license notices are included. The SHA-256 file identifies the downloadable ZIP; no Chrome Web Store publication or review is claimed.

## What was not verified

No Alpaca paper API credentials were supplied. Authenticated real-time/historical provider requests and genuine forward market performance were **not** exercised. The delivered adapter uses documented market-data GET routes and is validated with explicit test fixtures; this does not prove a particular user's account has IEX entitlement. Opening settings and saving credentials is not labeled successful provider authentication. Missing or denied access remains WAIT, with source/error information. No live profit, statistically calibrated win probability, broker fill, real order or continuous 24/7 hosting is claimed.
